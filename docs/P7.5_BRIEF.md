# 📋 P7.5 Brief — Offline-First Audit & Hardening

> **Status:** ✅ เสร็จ (audit) · **Date:** 2026-08-04
> **ที่มา:** มติผู้ใช้ 2026-08-04 (สำคัญมาก — Jan พังตอนเน็ตหลุด เราต้องไม่พัง)
> **หลักการ:** local-first, cloud-optional — ทุกหน้า/ฟีเจอร์ทำงานได้ 100% โดยไม่มีเน็ต

---

## 🎯 เป้าหมาย

ยืนยันว่าระบบ **ใช้งานโมเดล local ได้จริงแม้ไม่มีเน็ต** (จุดที่ Jan ใช้ไม่ได้) — ตรวจทุก feature ว่าไม่ hang/error เมื่อ offline

## 🔍 ผลการ Audit (ตรวจสอบโค้ดจริง)

### ✅ ทำงานได้ 100% offline (local-only)

| Feature | หลักฐาน |
|---------|---------|
| **Chat/generate** | เรียก `/v1/chat/completions` → local server → llama-server (local) |
| **Models scan/load/unload** | `api_server.py:444` ใช้ `get_model_search_dirs()` (local dirs เท่านั้น) ไม่มี HF call |
| **Stats / Issues / Usage / Logs** | ทั้งหมด local API |
| **Assistants (P7.2)** | `data/assistants/*.json` local |
| **MCP stdio (P7.4)** | เชื่อม stdio server (local process) |
| **Config** | local |
| **Date/time** | local datetime |

### 🟡 ต้องใช้เน็ต (แต่ fail gracefully — ไม่ hang/error)

| Feature | พฤติกรรม offline | หลักฐาน |
|---------|------------------|---------|
| **Hub search/download** | `HubUpstreamError` → **HTTP 502** (ไม่ fake) + offline banner | `hub.py:84,185` timeout 10s |
| **Hub model detail** | 502 + offline banner | `hub.py:830` timeout 15s |
| **MCP sse** | disconnected state | `mcp_host.py` |

### ✅ กลไกป้องกัน hang (มีอยู่แล้ว)

- **Timeout ทุก network call** — `apiJSON` abort 15s default / 20s hub (`api.ts:26`)
- **Offline banner honest** — `HubPage.tsx:515` "offline" (ไม่ fake list)
- **502 แทน fake** — `hub.py` "HF unreachable → 502, never a fake result"

---

## 📌 สรุป verdict

**ระบบ offline-first อยู่แล้ว** ✅ — core features (chat/models/stats/issues/assistants/MCP) ทำงานได้ 100% โดยไม่มีเน็ต มีเพียง Hub (HF) ที่ต้องใช้เน็ต แต่ fail gracefully ไม่ hang/error

**ต่างจาก Jan:** Jan พึ่ง cloud services (model list/telemetry/auth) → เน็ตหลุด = ใช้ไม่ได้ ระบบเรา **local-first** → เน็ตหลุด = ยังใช้ chat + models ได้เต็มที่

---

## 🧪 เกณฑ์จบ P7.5 (ผ่าน)

1. ✅ ตัดเน็ต → chat/models/issues/assistants ยังทำงาน
2. ✅ Hub แสดง offline banner (ไม่ fake/hang)
3. ✅ timeout ทุก network call
4. ✅ 502 แทน fake data

---

## ⚠️ หมายเหตุ (งาน QA ต่อ — ไม่ blocking)

- ยังไม่ทดสอบ **ตัดเน็ตจริง** (ต้อง mock network) — ตรวจจากโค้ดเท่านั้น
- Hub offline banner มีอยู่แล้ว แต่ยังไม่มี **test อัตโนมัติ** สำหรับ offline path
- MCP sse offline state ยังไม่ทดสอบ E2E
